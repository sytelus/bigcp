# 2026-07-29 review: deviations, VISION alignment, and hardening

This document records every change made in the 2026-07-29 whole-repository
review, the reason for each, and the verification that closed the pass. Scope
of the review request: align PLAN.md with the owner's updated VISION.md (whose
testing guidance was **not modified** and drove several changes below),
disposition all 21 `PLAN_DEVIATIONS.md` entries, deep-review the code for
correctness/quality/duplication/consistency, adjust the test suite within the
VISION guidance, verify the structure supports future scope, and repair stale
documentation.

## 1. VISION-driven PLAN.md changes

The owner added two things to VISION.md: hardened test guidance (tests must be
confined, harmless, and must never create hundreds of thousands of files, risk
drive lifespan, or destabilize the machine) and a requirement to collect
judiciously minimal live-run insight.

- **§12.0 Absolute test prohibitions** — new normative section: no
  large-scale real trees, no endurance/TB-class writes, no forced disconnects
  (physical *or* virtual), no reboot/shutdown/crash-inducing tests, ever, with
  no approval path. Scale and device-loss behavior are validated by synthetic
  enumeration, deterministic kill-point simulation, and fault injection only.
- **§12.4/§12.5/§12.6/§12.7** — chaos passes bounded (no 8-hour soaks),
  device-loss cells graceful-VHDX/fault-injection only, workload W1s capped at
  20k×4 KiB, the long-run suite removed rather than deferred.
- **§8.7** — bounded write budgets and KPI collection rewritten to fit the
  prohibitions.
- **§5.14 `--analyze`** — the live-run insight requirement designed as: five
  fixed size-class buckets (≤64 KiB, ≤1 MiB, ≤16 MiB, ≤256 MiB, >256 MiB) with
  per-bucket file counts, bytes, and cumulative seconds; a top-20
  slowest-copies table; a 5-second stat cadence (30 s without the flag); one
  `analysis` JSONL event and one optional report section. Bounded by
  construction — no per-file log lines, no unbounded tables — satisfying
  "minimal insight without significant slowdown or unreasonable log sizes".
- **§13.2 Implementation status (pre-1.0)** — the release-work registry that
  the deviation dispositions point into.
- **§13.3 Extension seams** — see §5 below.

Companion doc updates: `docs/TESTING.md` (prohibited-not-deferred, no approval
path), `BENCHMARKS.md` (no endurance path; extrapolations labeled),
`docs/PRODUCTION_READINESS.md` (release-blocking list rewritten under the
prohibitions), README.md (fault-injection-only device loss, drive-removal
guidance, FAQ).

## 2. Deviation dispositions (all 21)

Every entry in `PLAN_DEVIATIONS.md` was judged on merit; the file was
rewritten as a disposition table. None violated VISION. Two categories:

- **Accepted (normative), 8 entries** — the deviation is the better design and
  PLAN.md was amended to match: uniform temp+rename for all sizes (I5);
  tentative checkpoints with resume-time digest verification instead of
  per-checkpoint flushes (I13: verification is the integrity guarantee);
  deterministic size-tier checkpoint boundaries; the ADS-open disposition
  micro-window documented in §4.3; §5.17 files-only verify read-back honesty;
  extra destination ADS never deleted; JSONL as sole telemetry (§14.3); I10
  enforced in core, not just CLI.
- **Accepted (release work), 13 entries** — legitimate pre-1.0 gaps (IOCP
  transport, fault/chaos harness, elevated matrix, differential runs,
  performance evidence, etc.) now tracked in PLAN §13.2 as release-blocking,
  with the newly prohibited forms (8-hour soaks, million-entry real trees,
  any forced disconnect) replaced by their simulation equivalents.

A maintenance rule at the end of the file requires future deviations to be
dispositioned the same way.

## 3. Code fixes (with rationale)

Confirmed defects, most severe first:

1. **EFS preservation was impossible as written** (`win/file.rs`,
   `core/engine.rs`). Temps are created delete-pending; path-based
   `EncryptFileW` can never open them, so encrypted sources silently copied
   plaintext. Fix: request `FILE_ATTRIBUTE_ENCRYPTED` at temp creation;
   `efs_downgraded_for` checks the temp's actual attribute and reports a
   per-file downgrade when creation-time encryption did not take (best-effort
   is inherent — sparse+EFS are mutually exclusive and the destination volume
   may refuse).
2. **Device profiling dead on all production paths** (`win/device.rs`).
   Production roots are `\\?\`-prefixed; the drive-letter check rejected them,
   so profiling always fell back. New `device_path_for_root` strips
   `\\?\`/`\\.\` before classification; three unit tests pin it.
3. **`--dry-run` and unrelated flag changes destroyed resume checkpoints**
   (`core/copy.rs`, `core/journal.rs`). Dry-run no longer opens the journal at
   all, and the option-hash gate was replaced by `RESUME_PROTOCOL_SIGNATURE`:
   checkpoints self-validate on reuse (source/temp identity + prefix digest),
   so option changes must not wipe them.
4. **Journal brittleness** (`core/journal.rs`). One interior CRC-bad record
   used to truncate everything after it, discarding good checkpoints. Now only
   a genuinely torn final line truncates; interior bad records are skipped and
   counted (surfaced as a run warning). `append` self-heals a missing trailing
   newline. Clean runs `compact()` the journal to job header + live
   checkpoints via temp+rename, bounding growth.
5. **I6 accounting was tautological** (`core/model.rs`, `core/copy.rs`).
   `files_discovered` was incremented by the same code path that recorded
   outcomes, so reconciliation could never catch a dropped file. Discovery is
   now counted at enumeration (`note_file_discovered`), outcomes separately;
   join failures account whole subtrees as `NotAttempted`; clean cancellation
   emits a `canceled_subtree` warning instead of an error.
6. **Symlink fidelity** (`win/reparse.rs`). `PrintName` is cosmetic and can
   lie; `SubstituteName` plus `SYMLINK_FLAG_RELATIVE` are now authoritative,
   and volume-GUID (`\??\Volume{…}`) targets are refused rather than
   reinterpreted.
7. **Worker panic → run deadlock** (`core/worker.rs`). A panicking worker took
   its completion message with it. `catch_unwind` converts a panic into an
   Internal `worker_panic` file error; the run completes and reports.
8. **Exit-code contract** (`cli/main.rs`). clap usage errors exited 2
   (colliding with "objects failed"); now 5. `--help`/`--version` exit 0.
   `NO_COLOR` is honored. Invariant breaches write the report (integrity
   "failed") before exiting 6.
9. **Smaller confirmed fixes**: sparse enumeration rejects a zero-range
   progress stall (would create silent holes); `DestinationTemp::resume`
   enforces the full opaque-name shape and rejects `:` (the ADS trick);
   stale `DRIVE_NO_ROOT_DIR` error replaced with a real NotFound;
   `ObjectMetadata`'s misleading `PartialEq` removed (ea_size asymmetry);
   `SkippedDifferent` now records what differed (old size/mtime/attrs,
   destination-newer); dropped ADS during directory-stream copy surfaces as a
   warning instead of vanishing; dead code removed (`skip_cloud` branch,
   `write_bytes_for_test`, `stream_bool_result_for_test`,
   `metadata_last_error_for_test`, a no-op pre-rename flush).

Reviewed and deliberately **not** changed now (registered in PLAN §13.2 /
TESTING.md instead, with reasoning): mid-file cancellation polling (kill is
already safe via the temp lifecycle), `ReparseTemp`/`DestinationTemp`
unification (belongs with the §13.3 trait extraction), verify.rs
error-vs-divergence conflation and pre-hash metadata short-circuit, and a
handful of P3 nits — each was judged not worth destabilizing a verified tree
for in this pass.

## 4. Test-suite changes (all within VISION guidance)

- **Structural enforcement of the scale prohibition**: the testkit generator
  hard-caps scenarios at 10,000 entries and depth 32 (`HARD_ENTRY_LIMIT`,
  `HARD_DEPTH_LIMIT`) — a scenario file cannot ask for a prohibited tree.
  `scripts/check-test-safety.ps1` was rewritten: substring scan for
  destructive storage commands (diskpart, Format-Volume, VHD mount/dismount,
  shutdown, raw device paths, …) across crates, scripts, and CI, plus
  anchored assertions that the guard code still exists.
- **Added tests**: device-path prefix handling (×3), symlink
  SubstituteName/relative-flag/volume-GUID (×3), interior-bad-journal-record
  skip, clean-end compaction, outcome-without-discovery loudness, and the
  end-to-end `--analyze` contract.
- **Adjusted tests**: e2e assertions that pinned pre-compaction journal
  contents now assert the compacted invariant; the cancellation test asserts
  zero errors plus the `canceled_subtree` warning.
- **No test was removed for violating VISION** — the existing suite was
  already sandbox-confined; the sandbox marker check was tightened to a
  non-following metadata probe.
- The next tranche of safe, small tests (E19 aliasing, E41 replace=false,
  locked destination, hard links, long paths, Unicode, stale journal, run
  lock) is registered in `docs/TESTING.md` in priority order.

## 5. Extensibility (future scope, not enabled)

PLAN §13.3 "Extension seams" now records how each future direction lands
without a rewrite, verified against the current tree: the platform boundary is
the `bigcp-win` public surface (no `windows_sys` outside that crate — checked);
UNC/network support is a policy gate in `path.rs`/`volume.rs`, not scattered
assumptions; FAT/exFAT arrives via `VolumeCapabilities` flags plus the
ADR-0020 checklist (code switches on capabilities, not filesystem names);
efficient same-drive copy plugs in at the transport port; WSL/Linux/macOS is a
trait extraction of the win surface. Structural rules: no destination-write
primitive outside the temp types, capability flags not FS-name switches.
