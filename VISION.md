We wish to create a brand new command line tool called bigcp that will work in Windows. Currently, there is robocopy utility available on Windows but it still gets very slow when it encounters too many small files. It seem to require different options for efficient large file copy and yet other options for network copy etc. It has been often observed that in these variety of conditions robocopy achieves very suboptimal throughput. Our tool is going to overcome these issues. Our tool will also exclusively target modern SSDs and magnetic hard drives. It will take advantage of design, architecture and properties of these drives to maximize the throughput. Additionally the tool may judiciously use threads, proper APIs, fast data streaming, large bursts, large buffers, techniques such as async io, hardware details on individual drives, characteristics of USB-C connections or anything else that may be applicable, useful or relevant to maximize the throughput when it is possible. It will also take advantage of modern machines such as current PC with many cores, new gen PCIe bus, USB-C connection, huge amount of RAM (at least 32 GB but often 64 GB) and so on. You may investigate various read and write methods that allows maximizing throughput for SSD and HDD while connected via USB-C. Our tool must be efficient, robust and extremely reliable. You will only use official APIs and/or reliable or proven libraries. You may chose any suitable language including C++, Rust or Python. The tool must not miss copying files or copy them incorrectly or partially or in corrupt way because of bugs.

There is no need to implement full suit of arguments as in robocopy or other tools to keep things simple and maintainable. The tool should use defaults that is expressed by following robocopy arguments: /E /J /COPY:DTA /DCOPY:DATE /R:0 /W:0 /V /FP /ETA /SJ /SL. Additionally, our tool will be optimized for SSDs and HDDs and primarily USB-C as well as machines with many cores and very large RAM. Again, to keep things simple, there is no need to implement optimizations for other scenarios (such as networked copy, old OS or old machines) and you may assume this is our primary case.

The tool must provide beautiful modern terminal based UX with colors, formatting, progress and variety of information that may be useful and let users know what is going on. You may decide to build dashboard kind of UX if needed and if it is more useful. The tool should be able to resume more or less at same point if it was abruptly or intentionally terminated and re-run. The tool must avoid re-copying files if they already exist at destination. You may review how robocopy and other tools use fast and efficient heuristics to determine if source and destination files were same and, if there are opportunities, improve on them. The tool must produce log file that can be programmatically parsed. The tool should be conscious about not producing unnecessary disk io. The tool should offer verify mode to verify if all files have been copied correctly in efficient manner.

It may happen that file copy generates errors. The tool should log those errors and provide some running tally of errors, why are they happening and perhaps some hints to resolve them in next re-run when possible.

Above everything, reliability is the most important goal for this tool. This means when tool says X was successfully copied and Y failed, user can be sure that is indeed correct and that file paths, content, attributes are correct. However, tool should strive to avoid unnecessary checks that may reduce throughput. The tool should never corrupt files or delete them when they also didn't exist in source as it will cause data loss. The tool should also not produce any extra files that user didn't expect. The tool must treat source strictly as read-only (except for generating log or reports or temporary files if source drive is specified for those purposes). The tool should produce summary of how many files were successfully copied, how many failed, breakdown of failures by top level folders and reason, throughput achieved, maximum possible throughput and so on. In terminal UX, user should be able to navigate and examine more details about different aspects of your report. User should be able to also invoke tool latter with report file as argument to re-examine report at later date. The report should include any other useful details such as throughput bottlenecks, time started, time ended, slowest portion, fastest portion, any hints to improve throughput for next run when possible and so on.

Your job is to first review all current techniques to maximize copy throughput while taking advantage of modern hardware such as current machine and then design complete algorithm, architecture and implementation for the tool that will be reliable, robust and maximize the throughput while dealing with variety of circumstances such as huge number of very small files, very large files, tons of directories, source and destination drives with mismatched speeds and so on. You will study existing techniques to deal with these various scenarios and when neccesory create your own techniques or improve upon exisitng ones. You will also throughly study various edge cases implemented in other code basis and make sure you cover them in bigcp when they are relevant. You may also examine various reliable and popular open source projects which might have some success with the same goals. Your plan will include architecture, implementation details, finer points of everything, reasoning for your choices, test plan for various scenarios as well as catching potential robustness and reliability bugs and anything else you think that may be important or helpful. You will also include guidance on document to create and instructions on maintainable code so any future maintainer can maintain it without having to ask any questions to anyone. Your plan should have all the necessary details so an engineer can faithfully and reliably implement your vision and intention. You will save this plan in PLAN.md.
