# High-confidence improvements to `PLAN.md`

This review incorporates the current `VISION.md` clarifications: Windows 11 22H2 or later; FAT32/exFAT support remains required; the source tree may be assumed exclusive and stable; system files are excluded by default with explicit reporting and an override; partial resume is desirable for very large files but must be integrity-safe; and performance features such as `SetFileValidData` must not weaken reliability.

- **[P0] Redesign partial-file resume around durable checkpoints.** The current design trusts a journal watermark after completed writes and, without hashing, resumes without validating the prefix (§5.12). I/O completion does not guarantee that data survived power loss, unsafe removal, or a bridge failure, especially because the journal normally lives on a different volume and may become durable before destination data. A safe checkpoint must order operations as: complete prefix writes, make the destination prefix durable, append the watermark, and make the journal record durable. If that cost is unacceptable, restart the file rather than trusting a non-durable watermark.

- **[P0] Correct the resumed-hash algorithm.** Re-reading only the destination prefix and using it to rebuild the source hash state does not prove that the prefix matches the source; it produces a hash partly derived from destination data. Store independent source-prefix digests at durable checkpoints and compare them on resume, or read and compare both source and destination prefixes. Do not claim that hashing the destination prefix alone verifies it.

- **[P0] Never use a size-and-mtime-matched hash cache for authoritative verification.** Standalone verify currently skips reading the source when a cached hash matches size and mtime (§5.17). That reintroduces the exact false-negative condition full verification should detect: changed content with preserved size and timestamp. A full verify must read both current files. Cached hashes may support an explicitly weaker, clearly labeled trust-cache mode, but must not produce the same `verified` result.

- **[P0] Enforce the stable-source assumption and fail on violations.** `VISION.md` now permits assuming an exclusive, stable source tree. Preserve that simplifying assumption, but re-query size, last-write time, and file identity after reading using metadata operations that add no source data I/O. If a violation is detected, do not commit the temp file; report `source_changed` or `source_unstable`. Hashing whatever bytes happened to be read is not proof of a stable source version.

- **[P0] Protect the final commit from destination races.** Classification and replacement can be separated by a long interval. Another process could create or modify the destination in between. New files must use `CREATE_NEW`, not an overwrite-capable disposition. Replacements should record destination volume/file ID and change metadata during enumeration, revalidate immediately before rename, and fail with `destination_changed` if the target is no longer the same object. This is necessary to uphold the promise that bigcp does not overwrite unrelated data.

- **[P0] Align the copy contract, skip classifier, and verifier with the clarified metadata scope.** File and directory timestamps remain required and should include creation, last-write, and last-access timestamps wherever the destination filesystem can represent them. “Same” must compare or repair every required timestamp and basic attribute, not merely size, last-write time, and a subset of attributes. ADS and EAs must be decided explicitly rather than inherited ambiguously from Robocopy flag shorthand: the reliability-oriented recommendation is to preserve file and directory ADS on NTFS/ReFS and preserve directory EAs because `/DCOPY:DATE` explicitly includes `E`; file EAs can remain out of scope unless separately required. On FAT32/exFAT, which cannot represent these NTFS features, preflight and report the degradation and require an explicit policy for whether the file may still count as successfully copied. Compression state and sparse allocation layout are not correctness requirements. They may be used as transparent performance optimizations, but a logically identical dense or uncompressed destination is correct and must not cause recopy churn.

- **[P0] Define what “copied successfully” means with respect to durability.** The small-file finalizer says buffered-write errors can surface at `CloseHandle`, while flushing is optional (§5.8 and §7.2). Windows does not guarantee that closing a file forces buffered data to persistent media. Define and report distinct logical-completion and durable-completion guarantees, or make the reliability-oriented mode durable by default. The report must state which guarantee applied; it must not imply power-loss durability from `CloseHandle` alone.

- **[P0] Replace lexical path checks with handle-based identity and containment checks.** `GetFullPathNameW` makes a path absolute but does not resolve reparse points or prove identity. Open source and destination roots, resolve their final volume paths, record file IDs, and reject aliases or overlaps by identity. Also address reparse-point changes in destination ancestors, which can redirect a write outside the intended tree or back into the source.

- **[P0] Add explicit concurrent-run locking.** Two bigcp runs targeting overlapping destination trees can independently classify and replace the same entries. Require an exclusive destination-root lock or a robust overlap registry keyed by resolved volume/file identity. Journals must be per-run, while temp-file ownership and resume eligibility must be coordinated across runs.

- **[P1] Fix directory creation and completion ordering.** “DirCreate items run ahead” does not guarantee that a file engine cannot consume a dependent file before the meta engine finishes creating its parent (§5.7). Directory creation needs an explicit completion dependency or should occur synchronously before publishing child work. Register a directory and its pending-item count before emitting its file items so a fast outcome cannot reach the coordinator before the tracker exists.

- **[P1] Make temporary names valid for maximum-length filenames.** Appending `.<runid8>.bigcp-part` to a 255-character filename necessarily exceeds the component limit. Use a short opaque sibling name independent of the final filename, map it to the final name in the journal, generate a sufficiently large random nonce, and create it with `CREATE_NEW`.

- **[P1] Rework free-space forecasting.** `discovered_bytes - skipped_bytes` is not the required allocation. Replacement temporarily requires space for both old and new data; ADS, cluster rounding, compression, sparse-range optimization, and block cloning change the estimate. Report a conservative range and reserve enough for the largest in-flight replacement. Do not promise an exact shortfall unless the calculation covers every allocation path.

- **[P1] Make rename fallbacks failure-atomic.** If a fallback clears read-only, hidden, or system attributes on an existing destination and the subsequent rename fails, bigcp has modified a user file without completing the copy. Save and restore attributes on every failure path, verify that replacement remains on the same volume, and test every fallback independently on each supported filesystem.

- **[P1] Reject unknown reparse tags by default.** Copying arbitrary third-party reparse buffers verbatim is not guaranteed to be portable or meaningful. Support symlinks and junctions as required. Report unknown tags as unsupported unless the user explicitly requests raw reparse copying and accepts the risk.

- **[P1] Model timestamps per field and per filesystem.** A single filesystem-wide “10 ms exFAT / 2 s FAT” rule is incomplete. Creation, modification, and access timestamps have different resolution and representation; FAT access time is date-only. Project each source timestamp into the destination field’s representable form and compare that projected value. Tests must prove that a completed rerun reaches a stable all-same state without losing the timestamp guarantees the destination can represent.

- **[P1] Keep device-profile conclusions advisory.** `IOCTL_STORAGE_GET_HOTPLUG_INFO` does not provide a complete, authoritative reading of user-visible cache policy, and USB bus type plus a small maximum-transfer length is not reliable proof of BOT versus UASP. Record uncertain conclusions with confidence levels or inspect the actual driver stack. Do not force a performance policy solely from a heuristic device classification when direct measurements disagree.

- **[P1] Align the OS capability table with the Windows 11 22H2 minimum.** `PLAN.md` still promises Windows 10 1809 and contains fallback complexity justified by that target. Update the supported environment to Windows 11 22H2 or later, remove obsolete compatibility branches where possible, and retain runtime feature detection only for filesystem, driver, and device differences that still occur on supported builds.

- **[P1] Define a rigorous accounting model.** Specify whether discovered objects include links, directories, and stream-bearing files; whether byte counters mean logical bytes, transferred bytes, allocated bytes, or verified bytes; and whether `meta_fixed` is a subset of `skipped` or a disjoint outcome. Make terminal outcome categories disjoint and publish separate logical/read/written/allocated/verified byte totals so reconciliation is mathematically unambiguous.

- **[P1] Make logs, journals, and reports failure-safe.** “Infallible-by-buffering” is not a valid property: the state device can fill, disconnect, or reject a flush. Write final reports through temp, flush, and rename; propagate log/journal/report failures into a distinct audit-integrity result; and ensure `run_end` is durable before claiming that the audit record is complete. Add journal compaction and retention rules.

- **[P1] Make performance gates reproducible rather than aspirational.** Document OS build, Defender state, cache state, dataset generation, source/destination preparation, warm versus cold runs, repetitions, median/variance, and thermal controls. Compare against the best measured configurations of Robocopy, CopyFile2, and FastCopy rather than one fixed Robocopy invocation. A diskspd comparison must use compatible I/O semantics and the lower of measured source-read and destination-write ceilings.

- **[P1] Rename “maximum possible throughput.”** The best observed five-second window is an observed peak, not a maximum, and application I/O occupancy is not physical-device utilization. Report observed peak, run average, file rate, queue starvation, and latency, followed by a confidence-rated bottleneck hypothesis. Avoid definitive source-bound or destination-bound claims based only on in-flight occupancy thresholds.

- **[P1] Add missing adversarial tests.** Extend the suite with concurrent invocations, destination changes between classification and commit, source/destination aliases, ancestor junction swaps, a destination hard-linked to a source file, maximum-length temp names, journal-durable-before-data ordering, log/report disk-full failures, rename failure after attribute clearing, and verification after content changes that preserve size and mtime. The oracle should also assert that no object outside the intended destination changed.

- **[P1] Remove implementation phases and human-management gates from the plan.** The current `VISION.md` says the plan does not need development phases, timelines, or team-coordination material. Remove or replace §13’s M0–M6 roadmap and “seven consecutive days”/fresh-engineer process gates with implementation dependencies, technical acceptance criteria, and test prerequisites attached directly to the relevant design sections.

- **[P2] Establish simple measured baselines before adopting complex machinery.** Start with a correct single-threaded implementation and a CopyFile2 baseline, then add destination joins, parallel enumeration, deferred finalization, custom IOCP, auto-tuning, ReFS cloning, or lock-free coordination only when isolated benchmarks demonstrate a material benefit. This reduces the number of interacting novel mechanisms that must be debugged simultaneously without precluding any proven optimization.

- **[P2] Correct internal contradictions and references before implementation.** The plan alternates between `/DCOPY:DAT` and `/DCOPY:DATE`, although `E` requests directory extended attributes and those EAs are later declared unsupported. It also refers to nonexistent Appendix E and §6.7, and points type conflicts to E31 instead of E27. Add a documentation consistency check for section references and a requirements traceability table that maps each explicit `VISION.md` requirement to one normative semantic rule and one acceptance test.
